Cómo está hecho

Todo el proceso se reconstruye con un comando (./scripts/load.sh) en unos 10 segundos.

  1. StagingLos 8 CSV entran tal cual, como texto, con \copy. Nada falla por un formato raro.
  2. CoreModelo tipado con claves primarias, foráneas y CHECK. Cada carga queda registrada en una tabla de auditoría.
  3. Validación9 controles comparan conteos y montos con el dataset original: 0 filas rechazadas.
  4. MartVista materializada a nivel de pedido. Ítems y pagos se agregan antes del JOIN para no duplicar montos.
  5. AnálisisFunciones de ventana, cohortes, RFM, curva ABC, GROUPING SETS y percentiles.
  6. PublicaciónSolo agregados salen a un JSON de 24 KB; esta página lo dibuja sin librerías externas.

Datos: Brazilian E-Commerce Public Dataset by Olist, licencia CC BY-NC-SA 4.0. Los datos son reales y anonimizados por Olist. Esta página solo publica agregados, bajo la misma licencia.

Montos en reales brasileños (R$). Pedido válido = todo pedido no cancelado ni marcado como no disponible.
